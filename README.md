# Sheba Parking Guide (חניה חכמה בשיבא) – unofficial

A static, mobile-first Hebrew web app: for each clinic / test at Sheba Medical Center (Tel HaShomer) it shows the best
place to park, the best entrance and step-by-step walking directions – by time of day.
**Not affiliated with Sheba.** Everything that is not an official lot is labelled
"טיפ לא רשמי – על אחריותך, בדוק שילוט במקום".

* Hebrew guide for adding tips: [`docs/GUIDE-he.md`](docs/GUIDE-he.md)
* Where every fact comes from: [`SOURCES.md`](SOURCES.md) · what is still unknown: [`OPEN_QUESTIONS.md`](OPEN_QUESTIONS.md)

## Flow (Google-Maps style)

1. **Search** a destination ("MRI", "מכון הלב"…), optionally change the time / accessible route chips.
2. **Map + bottom sheet**: route options as chips (recommended + alternatives, the official main garage is always offered),
   big "נווט לחניה" (Waze) button, Google Maps link, step list, "last verified", vote, "report a correction".
3. **Walking navigation**: instruction banner, live GPS dot, outdoor steps advance by GPS, indoor steps by tapping.

Deep links: `?dest=mri&time=22:00` (also `time=thu-22:30`, `acc=1`, `safe=1`, `opt=1`, `walk=1`).

## Run locally

```bash
npm run serve            # http://localhost:8080  (any static server works, no build step)
npm test                 # routing + crowd-tip tests (node --test, no dependencies)
npm run validate         # checks data/sheba.json and prints the TODO list
node tools/try.mjs mri 22:00 [accessible]   # recommendation from the command line
```

## Architecture

| Part | Where |
|---|---|
| Data (one file, no backend needed) | `data/sheba.json` – schema in the section below |
| Routing: ngraph.graph + ngraph.path (A\*), time-dependent blocking | `js/engine/router.js` |
| Ranking, safety rules, auto-generated Hebrew steps | `js/engine/recommend.js`, `safety.js`, `steps.js` |
| Attaching new points/tips to the walking graph | `js/engine/attach.js` |
| UI | `js/app.js`, `js/ui/*`, `css/app.css` |
| Tip editor (`?edit=1`) and admin queue (`?admin=1`) | `js/editor/*` |
| Backend (optional): Supabase tables, RLS, RPCs | `supabase/schema.sql` (+ tests in `supabase/test/`) |
| PWA | `sw.js` (list generated by `tools/update-sw.mjs`), `manifest.webmanifest` |
| Data import (re-runnable) | `tools/import-osm.mjs`, `tools/seed-official.mjs` |

### Why ngraph.path
Evaluated: OSRM / GraphHopper / Valhalla (need a server, street-oriented, no indoor/opening-hours model) vs.
**ngraph.path** (MIT, ~10 KB, runs in the browser offline, A\* with a `blocked()` hook that lets us exclude closed doors,
non-public passages and stairs per query without rebuilding the graph). Parking ranking, the time rules and the
Hebrew step generator are ~400 lines on top.

### Data model (`data/sheba.json`)
Every record carries `prov: { verified, lastVerified, source: osm|sheba-site|owner|crowd|generated, confidence, url?, todo? }`.

* `buildings` – OSM outlines + names; `publicInterior` marks lobbies that are public thoroughfares
* `destinations` – id, Hebrew `name`, `aliases` (search), `buildingId`, `floor`, `lat/lon`, `hint`, `nodeId`
* `parkings` – `type` garage|lot|street, `official`, `mainOfficial`, `rules: [{days, from, to, status: ok|paid|risky|forbidden, note}]`
  (first matching rule wins; no rule on an unofficial lot ⇒ never recommended)
* `entrances` – `publicAccess` yes|no|unknown (**only `yes` is ever routed**), `hours`, `floor`, `note`
* `safetyZones` – emergency lane / ambulance bay / disabled / fire access / helipad; parkings inside are excluded at all hours
* `graph.nodes` / `graph.edges` – the pedestrian graph: length, `indoor`, `stairs`, `wheelchair`, `public`, `hours`, `polyline`, `note`
* `routeNotes` – hand-written step lists that override generated text; node `landmark` / edge `note` do the same per point
* `gates` – campus gates with opening hours (shown as a notice, not routed)

### Recommendation rules
Filter by the selected time (rules, door hours, gate-independent) → exclude safety zones, private lots, `forbidden`,
unknown-hours unofficial lots → A\* from every remaining lot to the destination (closed/non-public edges and stairs
removed when "accessible") → score = walking minutes + penalty (`paid` +1, `risky` +8, unverified unofficial +3,
flagged by votes +10) → top 3, plus the official main garage as a fallback.

## Crowd tips (optional backend)

Without a backend the site works fully from `data/sheba.json`; `?edit=1` still lets you draft tips on your phone and
export an updated `sheba.json`. To accept tips from the public:

1. Create a free project at <https://supabase.com>.
2. SQL editor → run `supabase/schema.sql`.
3. Authentication → Users → add your e-mail; Providers → Email → **disable sign-ups**; then run
   `insert into public.admins (user_id) select id from auth.users where email = 'YOU@…';`
4. Authentication → URL configuration → add the site URL to the redirect list.
5. Put the project URL and the *anon public* key (public by design) in `js/config.js`, commit.

Anonymous visitors can only: insert a *pending* tip through `submit_tip()`, cast a vote through `cast_vote()`,
upload a ≤700 KB JPEG into a private bucket, and read approved tips + vote totals. Rate limits (5 tips/hour/device,
global cap), honeypot, size limits, tag stripping, safety checkbox + keyword flags are enforced **in the database**.
Approving is admin-only (`is_admin()` + RLS). Approved tips are cached in the browser for offline use and turned into
graph nodes/edges after approval (`js/data.js`).
Tips with ≥3 👎 (more than 👍) or not re-confirmed for 6 months are flagged and ranked lower.

## Deploy (GitHub Pages)

`.github/workflows/pages.yml` runs tests, regenerates the service-worker list and publishes on every push to `main`
→ `https://<user>.github.io/<repo>/`. (Pages on a **private** repo needs a paid GitHub plan; on a free plan the repo must be public.)
Repo → Settings → Pages → Source: **GitHub Actions**.

## Refreshing the data

```bash
npm run import:osm       # re-download OSM (Overpass → OSM API fallback) and rebuild; keeps official/owner/crowd records
npm run data:rebuild     # re-apply official seed + re-import from the cached OSM extract
npm run validate
```
Records edited in the editor get `prov.edited` and are never overwritten by the seed script.
